AI schedule import — rebuilt & moved into Schedule page DONE

Old flow read binary files as text and shipped garbage to a brittle keyword/regex parser, and only accepted PDF/DOCX. New flow:

Upload image / PDF / DOCX → AI extracts → editable preview (fix tasks & frequencies) → Save. Found under Schedule → Edit Mode → “Import from a document”.

Model does the fuzzy reading (handles any layout — tables, checkboxes, columns, free text). Code does the deterministic parts: strict JSON schema + validation, dedup, frequency normalisation, and saving. Nothing is written until you press Save.

AI provider — the one open decision

The extraction pipeline is wired and works; it just needs a working model behind it. Two options:

OptionWhat it needsNotes
OpenAI (current) A valid OPENAI_API_KEY Key in .env is expired (401). Best quality, but sends documents to OpenAI.
Local (recommended) Already installed here Ollama qwen2.5:7b + Tesseract OCR. Free, private (care-home data stays on-device), no key.
Local plan (proposed). Your machine already has Ollama (qwen2.5:7b, llama3.2:3b) and Tesseract 5.5. Plan:
  • PDF / DOCX → text is already extracted → qwen2.5:7b structures it. No vision needed. This covers most real schedules.
  • Images / scanned PDF → either Tesseract OCR → text model (zero new installs), or pull a small local vision model (better on messy tables/handwriting).
  • Reuse the OpenAI SDK pointed at Ollama’s OpenAI-compatible endpoint (localhost:11434/v1) behind a SCHEDULE_AI_PROVIDER switch, so you can flip local ⇄ OpenAI anytime.

My recommendation: go local with qwen2.5:7b, and start images on Tesseract OCR (nothing new to install) — upgrade to a local vision model only if OCR quality isn’t sharp enough. Removes the API-key blocker entirely and is testable immediately.
